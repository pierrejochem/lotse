# Lotse 0.1.0

The first release, a preview. Lotse is a message broker in Rust: reliable queues in the style of RabbitMQ and persistent streams in the style of Kafka on one replicated log, with exactly-once delivery. This release is for trying Lotse and building against it, not yet for data you cannot afford to lose.

## What is in it

- **Streams and queues on one log.** Partitioned streams with consumer groups, offsets and retention by age and size, or compaction to the newest record per key. Queues with acks, credit, redelivery, dead-letter queues, message TTL, delayed delivery, priorities, length limits and single active consumers. Exchanges route to queues (direct, topic, fanout, headers).
- **Exactly once.** Idempotent producers, transactions across streams and queues, and consume-transform-produce from a stream or a queue, all within one transaction.
- **Replication.** Every partition and queue is a Raft group. Nodes are added and drained at runtime, groups spread over them by themselves, leaders move to their preferred nodes, and a cluster upgrades one node at a time without stopping.
- **Secure by default.** TLS 1.3 on every connection with certificates from the cluster's CA; clients sign in with a certificate, SCRAM-SHA-512, OAUTHBEARER or an access token; tenants and six roles are checked on every request.
- **Operations.** Prometheus metrics, health and readiness endpoints on every node, `lotse certs` for the CA and certificates, restart turns for upgrades, and `lotse mcp`, which lets an AI agent work with a cluster as the user who signed in.
- **The management console.** A web UI and HTTP API that act as the signed-in user, serving HTTPS with a certificate of its own.

## What you get

For x86_64 and aarch64 Linux, of each program, `lotse` (the node and its tools) and `lotse-console` (the console):

- a static binary and a tarball with the systemd, OpenRC and sysvinit scripts;
- a `.deb` (systemd, or sysvinit without it), an `.rpm` (systemd) and an `.apk` (OpenRC);
- the images `ghcr.io/pierrejochem/lotse` and `ghcr.io/pierrejochem/lotse-console`, tagged `0.1.0`, `v0.1.0` and `latest`;
- the Helm chart in `packaging/helm/lotse`, which runs the nodes and, with `console.enabled`, the console.

The [guide](https://pierrejochem.github.io/lotse/) covers installing, running and using Lotse.

## Checking what you downloaded

The release was built twice on two runners and published only because both builds matched byte for byte, as did both builds of each image. Check your downloads against `SHA256SUMS`:

```sh
sha256sum --check --ignore-missing SHA256SUMS
```

`packaging/release.sh --verify SHA256SUMS 0.1.0`, run in a checkout of the tag with the tools `packaging/release.env` pins (`make release-tools`), builds the release again and compares every file. The packages are not signed, so `SHA256SUMS` and the reproducible build are the checks; Alpine installs the `.apk` with `--allow-untrusted`.

## Not in this release

- **Client SDKs.** The Java, Kotlin, C# and Node.js clients are in `sdk/` and tested against real nodes, but not yet on Maven Central, NuGet or npm; build them from source. The Rust client is the `lotse-client` crate in the repository, not on crates.io.
- **Known gaps.** What is not built yet and the limits that were decided are in [docs/status.md](https://github.com/pierrejochem/lotse/blob/v0.1.0/docs/status.md). Among them: the Helm chart does not add or remove nodes, every pod mounts every node's key, the console and `lotse mcp` read their HTTPS certificate only at start, and access tokens cannot be narrowed to fewer roles than their owner has.

## Upgrades and compatibility

This release sets cluster version 0.1, the baseline of the on-disk and node-to-node formats. The next minor release runs beside it and upgrades a cluster in place, one node at a time; skipping a minor release means two upgrades. Beyond that, 0.x makes no promise: requests, settings and the client APIs may still change, and each release's notes say what did.

## Reporting a problem

Report bugs as GitHub issues. Report a vulnerability privately, as [SECURITY.md](https://github.com/pierrejochem/lotse/blob/v0.1.0/SECURITY.md) says.
