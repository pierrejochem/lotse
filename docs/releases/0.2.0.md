# Lotse 0.2.0

A release of the brokers, the console and the SDKs. Its cluster version is 0.2: a 0.2 node runs beside 0.1 nodes during a rolling upgrade, and the new formats are written only once `lotse upgrade finalize` raised the cluster version to 0.2.

## What changed

- **Storage quotas.** A cluster admin sets a storage limit per tenant, and tenant admins divide it with limits on name prefixes; every replica counts. Once a limit is full, new data under it is refused with `QUOTA_EXCEEDED`, which clients do not retry, while reads, acks and deletes go on. Set and read limits with `AlterQuota` and `DescribeQuotas`, `alter_quota` and `describe_quotas` in the clients, `set_quota` and `describe_quotas` in `lotse mcp`; watch them with `lotse_quota_used_bytes`, `lotse_quota_bytes` and `lotse_quota_full` ([ADR 0147](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0147-storage-quotas-per-tenant-and-prefix.md), [Storage quotas](https://pierrejochem.github.io/lotse/admin/storage-quotas.html)).
- **Segments close by age.** A runtime stream's or queue's active segment closes once it has held data for an hour, so a drained queue or a stream past its retention frees its space without new data. Set the node's age with `[cluster] segment_ms`, and a resource's with `segment.ms` through `AlterConfigs` once the cluster version is 0.2 ([ADR 0146](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0146-segments-close-by-age.md)).
- **Reads in the client's zone.** A client with a `zone` fetches from the leader, which names a current voter in that zone (`preferred_replica`), and the client goes there without asking for metadata. Committed offsets and admin reads go to a node in the client's zone too, and that node serves them only once it has applied everything the client has seen, so a client reads its own writes ([ADR 0141](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0141-reads-in-the-client-s-zone-with-read-your-writes.md)).
- **Steadier leaders.** A node writes the groups of a round to disk together, so a busy disk no longer makes a round outlast an election timeout ([ADR 0143](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0143-a-round-persists-its-groups-together.md)). Groups elect after a second by default; set it with `[cluster] election_timeout_ms` and `heartbeat_ms` ([ADR 0144](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0144-groups-elect-after-a-second.md)).
- **No false unknowns.** A node whose metadata may be behind answers a name it lacks with `NOT_LEADER`, and every client asks another node instead of reporting the stream or queue unknown ([ADR 0145](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0145-a-node-behind-does-not-call-a-name-unknown.md)).

## What you get

`lotse` and `lotse-console` as static binaries, tarballs, `.deb`, `.rpm` and `.apk` packages and the images `ghcr.io/pierrejochem/lotse` and `ghcr.io/pierrejochem/lotse-console`, for x86_64 and aarch64 Linux, built twice and published only when both builds match. For the first time the SDKs are released with the broker at its version: `dev.lotse:lotse-client`, `dev.lotse:lotse-client-kotlin`, `Lotse.Client`, `Lotse.Client.Codecs` and `@pierrejochem/lotse-client` on GitHub Packages and as files on this release, with `SHA256SUMS-sdk` ([ADR 0142](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0142-the-sdks-are-released-with-the-broker-on-github-first.md)).

## Upgrading

Upgrade one node at a time with the restart turn, as for any release ([ADR 0127](https://github.com/pierrejochem/lotse/blob/main/docs/adr/0127-rolling-upgrades-with-a-cluster-version-and-restart-turns.md)), then raise the cluster version with `lotse upgrade finalize`.
